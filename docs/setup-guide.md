# Setting up search by meaning, answers and chat

<!-- Written by scripts/write-setup-guide.mjs from packages/shared/src/setup-guide.ts and
     recommended-models.ts. Do not edit this file: change the source and run the script. -->

This is the guide Outpost shows at `/help/search-and-answers`, word for word. Checked on 16 November 2026.

Two things in Outpost are optional and switched off to begin with. **Search by meaning** needs nothing but its switch. **Answers and chat** need a free program called Ollama, which you install once.

Outpost itself never needs the internet. Getting Ollama and a model does, once; the steps that do are marked.

## Search by meaning

1. Open **Settings** and go down to **Search by meaning**.
2. Turn the switch on.
3. Wait. Outpost reads your library once and says how long is left: about 45 seconds for every thousand passages on a recent laptop, and about four minutes on a Raspberry Pi 5. You can close the page; it carries on. It is done when it says **Search now also finds things by meaning**.

That is all. Nothing is downloaded and nothing leaves the computer Outpost runs on. What you add later is read as it arrives. Turning the switch off keeps what was read.

## Answers and chat, with Ollama

Answers and chat are written by a language model: a program that writes text. Outpost does not include one. Ollama is a free program that runs one on your own computer, normally the computer Outpost runs on. Once it is set up, what you ask goes to Ollama and nowhere else.

Expect a helper, not an expert. For **Answer from my library** the model is given a few passages found in your documents and told to answer from those alone, with a number after each statement that opens the passage. When the passages found do not hold the answer it should say so, and with a small model and a short question that is often what you will see. Check anything that matters against the passage itself.

### Step 1: get Ollama

*This step needs the internet.*

#### Mac

1. On the Mac, open [ollama.com/download](https://ollama.com/download) in a browser and download Ollama for macOS. It needs macOS 14 (Sonoma) or newer.
2. Open the file that was downloaded, `Ollama.dmg`, and drag **Ollama** into the **Applications** folder.
3. Open **Ollama** from Applications. If it asks for permission to add its command to the Mac (a link in `/usr/local/bin`), allow it: step 2 uses that command.

#### Windows

1. On the PC, open [ollama.com/download](https://ollama.com/download) in a browser and download Ollama for Windows. It needs Windows 10 (version 22H2) or newer.
2. Open the file that was downloaded, `OllamaSetup.exe`, and follow it. It does not need an administrator.
3. Ollama then runs in the background, with an icon in the corner of the taskbar. Nothing else needs opening.

#### Linux

1. Open a terminal window. On most desktops the application is called Terminal.
2. Type this and press Enter. It is Ollama's own installer, and it may ask for your password:

   ```
   curl -fsSL https://ollama.com/install.sh | sh
   ```

3. When it finishes, Ollama is running, and it starts with the computer from now on (as a service called `ollama`).

#### Raspberry Pi

Use a Raspberry Pi 5, or a Pi 4, with the 64-bit Raspberry Pi OS. 8 GB of memory is the sensible size; 4 GB is enough for the smallest models in step 2. Ollama publishes a 64-bit ARM build for Linux, which is what a Pi needs. Its documentation does not mention the Raspberry Pi by name, and this project has not tried one.

1. Open a terminal window on the Pi.
2. Type this and press Enter. It is Ollama's own installer, and it may ask for your password:

   ```
   curl -fsSL https://ollama.com/install.sh | sh
   ```

3. When it finishes, Ollama is running, and it starts with the Pi from now on (as a service called `ollama`).

### Step 2: get a model

*This step needs the internet.*

A model is one large file that Ollama downloads and keeps. First open the place where commands are typed.

#### Mac

On a Mac, open **Terminal**: click the magnifying glass at the top right of the screen, type `Terminal`, then click **Terminal**.

#### Windows

On Windows, open the **Start** menu, type `Windows PowerShell`, select **Windows PowerShell**, then select **Open**.

#### Linux

On Linux, use the terminal window from step 1.

#### Raspberry Pi

On a Raspberry Pi, use the terminal window from step 1.

1. Type this and press Enter:

   ```
   ollama pull lfm3:1.7b
   ```

2. Wait for the download to finish: 1.7 GB. It is done when the line you type on comes back.
3. To see which models Ollama has, type:

   ```
   ollama ls
   ```

`lfm3:1.7b` is the one to start with, and a computer with 4 GB of memory can hold it. These are the small models Outpost suggests; all of them suit a laptop or a Raspberry Pi 5 with 8 GB. To get another, put its name in place of `lfm3:1.7b` in the command.

For a model's sizes today, open [ollama.com/library](https://ollama.com/library), choose the model, and look under **Tags**.

### Step 3: come back to Outpost

1. Open **Settings** and go down to **Answers from your library**. The **Chat** screen offers the same buttons until this is done.
2. Press **Look for Ollama on this computer**.
3. Outpost lists the models Ollama has, with one already chosen. Press **Use this model**.
4. Press **Try it**. Outpost asks the model for one word and shows what came back. The first try can take a minute, because Ollama loads the model into memory then. When it answers, answers and chat are switched on.

To use it: on the **Search** screen, type a question and press **Answer from my library**; or open **Chat**.

Chat can also let the model look things up in Outpost: places on the map, supplies, plans, the weather as last fetched and more. It is off until you switch it on under **Settings → Looking things up in Outpost**, and it needs a model that can call tools: **Which model** (under Settings) says which of the suggested ones do it well.

## When Ollama is on a different computer from Outpost

As installed, Ollama answers only the computer it runs on (address `127.0.0.1`, port `11434`). To let an Outpost on another computer use it, set `OLLAMA_HOST` to `0.0.0.0:11434` on the computer Ollama runs on.

### Mac

1. Open **Terminal**, type this and press Enter:

   ```
   launchctl setenv OLLAMA_HOST "0.0.0.0:11434"
   ```

2. Quit Ollama and open it again.

### Windows

1. Quit Ollama from its icon in the corner of the taskbar.
2. Open **Settings** (Windows 11) or **Control Panel** (Windows 10) and search for `environment variables`.
3. Click **Edit environment variables for your account**.
4. Make a new variable for your account named `OLLAMA_HOST` with the value `0.0.0.0:11434`, and click **OK**.
5. Start Ollama again from the Start menu.

### Linux

1. In a terminal window, type this and press Enter:

   ```
   sudo systemctl edit ollama.service
   ```

2. In the editor that opens, add these two lines, then save and close it:

   ```
   [Service]
   Environment="OLLAMA_HOST=0.0.0.0:11434"
   ```

3. Then type these two lines, pressing Enter after each:

   ```
   sudo systemctl daemon-reload
   sudo systemctl restart ollama
   ```

### Raspberry Pi

1. In a terminal window, type this and press Enter:

   ```
   sudo systemctl edit ollama.service
   ```

2. In the editor that opens, add these two lines, then save and close it:

   ```
   [Service]
   Environment="OLLAMA_HOST=0.0.0.0:11434"
   ```

3. Then type these two lines, pressing Enter after each:

   ```
   sudo systemctl daemon-reload
   sudo systemctl restart ollama
   ```

Then tell Outpost where it is:

1. Find the network address of the computer Ollama runs on, for example `192.168.1.20`.
2. In Outpost, open **Settings**, **Answers from your library**, **More options**, and in **Server address** type `http://192.168.1.20:11434/v1`, with your own address in place of `192.168.1.20`.
3. Press **Look for Ollama on this computer**. The address you typed is asked first. Then carry on as in step 3.

Ollama has no password: once it listens on the network, anyone on that network can use it. Outpost sends questions only to an address on this computer or on a private network. An address on the internet is refused unless whoever starts Outpost sets `OUTPOST_ALLOW_REMOTE_MODEL_SERVER=true`.

## When Outpost runs in Docker

Inside a container, “this computer” is the container, not the machine Docker runs on. Docker calls that machine `host.docker.internal`, and **Look for Ollama on this computer** tries that name by itself, after `127.0.0.1`.

With Docker Desktop, on a Mac or on Windows, the name works as it is.

With Docker on Linux, add this to the `outpost` service in `compose.yaml`, then start Outpost again:

```
extra_hosts:
  - "host.docker.internal=host-gateway"
```

If Ollama is still not found, tell it to listen on the network as in the section above: seen from a container, the machine it runs on is another computer.

## Three things that go wrong, and the fix

1. **Outpost says:** “Ollama was not found”, or “No model server answered”

   **What it means:** Ollama is not running, or it is on another computer.

   **The fix:** Start it. On a Mac, open **Ollama** from Applications. On Windows, open it from the Start menu. On Linux or a Raspberry Pi, type `sudo systemctl start ollama`. Then press the button again. If Ollama is on another computer, or Outpost runs in Docker, see the two sections above.

2. **Outpost says:** “It has no models yet”, or “This model is not on the model server”

   **What it means:** Ollama is running, but step 2 did not finish or the model has been removed.

   **The fix:** On the computer Ollama runs on, type `ollama pull lfm3:1.7b`, check with `ollama ls`, and press the button again.

3. **Outpost says:** The try gives up after a minute, or answers take minutes to start

   **What it means:** The model is still being loaded into memory, or it is too large for the computer.

   **The fix:** Try once more: the first request after Ollama starts is the slow one. If it is always slow, get a smaller model from the list in step 2, such as `gemma3:1b`, and choose it in Outpost.

## Other model servers

Ollama is not the only choice. Any server that speaks the same protocol works. Start it, type its address in **Settings**, **Answers from your library**, **More options**, **Server address**, and press **Look for Ollama on this computer**: the address you typed is asked first.

llama.cpp: `llama-server -m model.gguf` listens on `127.0.0.1`, port `9931`, unless told otherwise, so the address is `http://127.0.0.1:9931/v1`.

LM Studio: on its **Developer** tab, turn on **Start server**. Its documentation's examples use port `1234`, so the address is `http://127.0.0.1:1234/v1` unless you changed the port.

Neither has been tried with Outpost. Only their documentation was read.
